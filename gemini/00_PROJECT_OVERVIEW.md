# CMS LABORATORIUM KOMPUTER
## Project Overview

Versi: 1.0

---

# 1. LATAR BELAKANG

Laboratorium Komputer merupakan unit pendukung kegiatan akademik yang berperan dalam menyediakan fasilitas, layanan, serta sumber daya untuk mendukung proses pembelajaran, pelatihan, penelitian, dan pengembangan kompetensi di bidang teknologi informasi.

Seiring berkembangnya kebutuhan informasi, Laboratorium Komputer memerlukan media digital yang mampu menyajikan informasi secara terpusat, terstruktur, dan mudah diakses oleh mahasiswa, dosen, tenaga kependidikan, mitra kerja sama, serta masyarakat umum.

Informasi seperti profil laboratorium, fasilitas, kegiatan, berita, pengumuman, dokumentasi, prestasi, dan dokumen pendukung sering kali tersebar pada berbagai media sehingga menyulitkan proses pengelolaan maupun penyampaian informasi.

Untuk mengatasi permasalahan tersebut, diperlukan sebuah Content Management System (CMS) yang mampu menjadi pusat informasi digital Laboratorium Komputer secara modern, profesional, dan mudah dikelola.

---

# 11. PRINSIP PENGEMBANGAN

CMS Laboratorium Komputer dikembangkan dengan prinsip memaksimalkan fitur bawaan Laravel dan meminimalkan ketergantungan terhadap package pihak ketiga.

Tujuan:

- Mengurangi ketergantungan eksternal.
- Mempermudah pemeliharaan sistem.
- Mempermudah proses upgrade framework.
- Meningkatkan kontrol terhadap arsitektur aplikasi.
- Mempermudah dokumentasi dan transfer knowledge.

---

# 12. KEBIJAKAN PACKAGE

Prioritas penggunaan library:

1. Fitur bawaan Laravel.
2. Fitur bawaan PHP.
3. Implementasi custom sesuai kebutuhan.
4. Package resmi Laravel.
5. Package pihak ketiga yang benar-benar diperlukan.

Package pihak ketiga hanya digunakan apabila:

- Tidak tersedia solusi bawaan Laravel.
- Kompleksitas implementasi sangat tinggi.
- Menjadi standar industri yang umum digunakan.
- Memiliki dokumentasi yang baik.
- Mendapat persetujuan pengguna.

---

# 13. DEPENDENCY POLICY

Target implementasi versi awal:

- Tanpa package pihak ketiga non-resmi.
- Menggunakan komponen bawaan Laravel.
- Menggunakan komponen bawaan PHP.
- Menggunakan Tailwind CSS.
- Menggunakan Alpine.js.

Fitur yang direncanakan dibuat secara native:

- Authentication
- RBAC
- Dynamic Menu Management
- Settings Management
- Media Management
- Activity Log

---

# 14. KEBIJAKAN PENGGUNAAN PACKAGE PIHAK KETIGA

AI maupun developer tidak diperkenankan menambahkan package pihak ketiga secara otomatis tanpa persetujuan pengguna.

## Aturan Penggunaan Package

Sebelum menggunakan package pihak ketiga wajib:

1. Menjelaskan kebutuhan yang ingin diselesaikan.
2. Menjelaskan solusi menggunakan fitur bawaan Laravel.
3. Menjelaskan solusi menggunakan package.
4. Menjelaskan kelebihan dan kekurangan masing-masing pendekatan.
5. Meminta persetujuan pengguna.

## Format Rekomendasi

### Kebutuhan

Deskripsi kebutuhan.

### Solusi Native Laravel

Penjelasan implementasi menggunakan fitur bawaan.

### Solusi Package

Nama package dan alasan penggunaan.

### Analisis

Kelebihan:
- ...

Kekurangan:
- ...

### Keputusan

Menunggu persetujuan pengguna.

## Larangan

Tanpa persetujuan pengguna, AI maupun developer tidak boleh:

- Menambah package Composer.
- Menambah package NPM.
- Menginstal admin panel siap pakai.
- Menginstal CMS siap pakai.
- Menginstal package RBAC siap pakai.
- Mengubah dependency utama proyek.

## Default Assumption

Jika tidak ada persetujuan eksplisit:

- Gunakan fitur bawaan Laravel.
- Gunakan fitur bawaan PHP.
- Gunakan Tailwind CSS.
- Gunakan Alpine.js.
- Implementasikan fitur secara native.
